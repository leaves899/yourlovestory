## 1. 概述

### 1.1 什么是碎片日记

碎片日记是 day 模块的扩展功能。用户通过输入**来源**（触发来源）、**情绪**（感受）、**内容**（发生了什么）三个维度的碎片信息，系统将其整合为叙事写作的上下文，生成符合 day 写作原则的文本。

**核心思路：** 用户提供碎片 → 系统整合 → 生成叙事

### 1.2 与现有模式的关系

day 模块现有三种写作触发方式：

1. **日常对话模式** — 用户提供"事件线索"，系统生成叙事
2. **环境观察模式** — 系统根据 crush 角色档案中的环境信息，自动生成"在XX时，ta在做什么"的场景
3. **深度对话模式** — 系统分析对话截图，生成内心独白叙事

碎片日记是第四种：**用户提供多维度碎片信息，系统整合后生成叙事**。

### 1.3 前置依赖

| 依赖项 | 状态 | 说明 |
|--------|------|------|
| day/SKILL.md | 必需 | day 写作模块的核心文件，碎片日记基于此生成叙事 |
| crushes/{slug}/ 角色档案 | 必需 | crush 角色的静态信息，用于标签推荐和 Blind 模式匹配 |
| ../tags/ 标签库 | 可选 | 用于标签联想推荐，当前为"待创建"状态 |

## 2. 设计目标

### 2.1 核心目标

- **降低写作门槛** — 用户不需要想好完整场景，只需提供碎片信息
- **丰富叙事素材** — 来源+情绪+内容三维度，比单一事件线索更立体
- **保持 day 原则** — 碎片只是素材，叙事仍需符合 day 写作标准

### 2.2 day 写作原则

碎片日记生成的叙事需遵循 day 模块的核心写作原则（详见 [day/SKILL.md](../day/SKILL.md)）：

1. **第三人称叙事** — 使用"ta"而非"你"，保持叙事距离感
2. **感官细节优先** — 用具体动作、表情、环境描写代替抽象情绪
3. **留白与克制** — 不过度解释情绪，让读者自行感受
4. **时间线清晰** — 事件按时间顺序展开，避免混乱
5. **禁止破折号** — 不使用「——」，改用逗号或句号

### 2.3 设计约束

- 碎片只是**触发器**，不是叙事本身
- 系统负责整合碎片为叙事上下文，不改变 day 的写作流程
- 用户自由度分级：从完全自由到完全引导，适应不同状态

## 3. 数据模型

### 3.1 标签体系

碎片日记使用三层标签体系：

```
┌─────────────────────────────────────────────────────┐
│                    标签体系                          │
├─────────────────────────────────────────────────────┤
│  第一层：核心维度（必选，系统定义）                   │
│  ├── 来源标签：user / crush / ambient               │
│  └── 情绪标签：positive / negative / neutral / mixed │
├─────────────────────────────────────────────────────┤
│  第二层：场景标签（可选，系统推荐 + 用户自定义）      │
│  ├── 环境标签：与 crush 角色档案中的环境信息关联     │
│  └── 行为标签：描述 crush 的行为模式                 │
├─────────────────────────────────────────────────────┤
│  第三层：用户标签（可选，用户自定义）                 │
│  └── 碎片标签：用户为碎片添加的自由标签              │
│      （与标签库打通，支持联想推荐）                  │
└─────────────────────────────────────────────────────┘
```

### 3.2 碎片卡片结构

每个碎片包含以下字段：

| 字段 | 类型 | 必选 | 说明 |
|------|------|------|------|
| `id` | string | 是 | 碎片唯一标识，格式：`frag_{YYYYMMDD}_{HHMMSS}_{4位随机十六进制}` |
| `date` | date | 是 | 碎片日期 |
| `time` | string | 否 | 碎片时间（可选，如"14:30"）。为空时系统自动使用当前时间。存储格式：HH:MM |
| `origin` | enum | 是 | 来源：user / crush / ambient |
| `mood` | enum | 视模式而定 | 情绪：positive / negative / neutral / mixed。**模式约束**：Raw/Guided 模式可选（可跳过，null）；Themed/Blind 模式**必选** |
| `content` | string | 否 | 碎片内容（用户输入的文字），长度限制：10-500 字（Blind 模式）/ 5-500 字（其他模式） |
| `env_tags` | string[] | 否 | 环境标签（可选） |
| `behavior_tags` | string[] | 否 | 行为标签（可选） |
| `custom_tags` | string[] | 否 | 用户自定义标签（可选） |
| `writing_mode` | enum | 是 | 写作模式：raw / guided / themed / blind |
| `direction` | string | 视模式而定 | guided 模式选择的方向（仅 guided 模式**必选**）。注意：direction 是日期级别属性，当日所有 guided 碎片共享同一方向 |
| `theme` | string | 否 | themed 模式选择的主题（仅 themed 模式）：工作/学习、生活日常、约会/出行、情感交流、兴趣爱好、节日/纪念日、争吵/误会、和好/道歉 |
| `crush_slug` | string | 是 | 关联的 crush 角色标识 |
| `created_at` | datetime | 是 | 创建时间（ISO 8601 格式，系统自动生成） |
| `updated_at` | datetime | 是 | 最后更新时间（ISO 8601 格式，系统自动更新） |

### 3.3 情绪 Emoji 映射

碎片卡片中情绪使用以下 emoji 表示：

| 情绪 | Emoji | 说明 |
|------|-------|------|
| positive | 😊 | 开心、期待、温暖 |
| negative | 😢 | 难过、失落、在意 |
| neutral | 😐 | 平静、日常、无特别 |
| mixed | 😶 | 复杂、矛盾、说不清 |
| 未选择 | ⬜ | 跳过情绪标签时显示（仅 Raw/Guided 模式可跳过，Themed/Blind 模式必选） |

### 3.4 碎片存储

碎片存储在 crush 角色目录下：

```
crushes/{slug}/fragments/
├── 2026-05-30.json    # 按日期存储
├── 2026-05-29.json
└── ...
```

每个 JSON 文件结构：

```json
{
  "date": "2026-05-30",
  "crush_slug": "xiaomei",
  "fragments": [
    // 碎片列表...
    {
      "id": "frag_20260530_143000_a1b2",
      "time": "14:30",
      "origin": "crush",
      "mood": "positive",
      "content": "ta发了一个表情包",
      "env_tags": ["工作"],
      "behavior_tags": [],
      "custom_tags": ["可爱"],
      "writing_mode": "guided",
      "direction": "轻松的"
    },
    {
      "id": "frag_20260530_150000_c3d4",
      "time": null,
      "origin": "user",
      "mood": null,
      "content": "",
      "env_tags": [],
      "behavior_tags": [],
      "custom_tags": [],
      "writing_mode": "raw",
      "direction": null
    }
  ],
  "completed": false,  // 日期级别属性：该日期的写作是否已完成
  "writing_context": null,
  "created_at": "2026-05-30T14:30:00",
  "updated_at": "2026-05-30T15:00:00"
}
```

**字段说明：**
- `completed`：**日期级别**属性，表示该日期的写作是否已完成。`false` 表示可继续添加碎片或触发写作；`true` 表示已完成写作，碎片不可编辑（只读），不可重新生成叙事，不可添加新碎片，不可删除
- `writing_context`：写作上下文，存储 day 模块生成的叙事内容。与 day 模块的关系：
  - 碎片整合后作为输入传递给 day 模块
  - day 模块生成的叙事文本存储在 `writing_context` 字段中
  - 重新生成叙事时，覆盖原有 `writing_context` 内容
  - 删除碎片时，`writing_context` 中的叙事内容保留（仅删除碎片数据）

### 3.5 多 Crush 场景

- 每个 crush 角色独立维护碎片数据
- 切换 crush 时，碎片列表自动过滤为当前 crush 的碎片
- 碎片卡片中的 `crush_slug` 字段用于关联
- **切换时的处理**：当前正在编辑的碎片自动保存到原 crush，切换后显示新 crush 的碎片列表

**碎片与日期的关系：**
- 每个 crush 独立维护碎片数据，碎片按日期 + crush_slug 共同索引
- 切换 crush 不影响日期，同一日期可能有多个 crush 的碎片
- 示例：用户周三在 Crush A 创建了碎片，切换到 Crush B 后，周三的碎片列表显示 Crush B 的碎片；再次切换回 Crush A，周三的碎片列表显示 Crush A 的碎片（不显示 Crush B 的周三碎片）

### 3.6 碎片生命周期

**状态区分基准：当前日期 vs 碎片所属日期**

| 状态 | 说明 | 提醒机制 | 整合权限 |
|------|------|----------|----------|
| 进行中 | 碎片所属日期 = 当前日期，且有碎片未完成写作 | 次日主动提醒 | 可与新碎片整合 |
| 未完成（7天内） | 碎片所属日期 < 当前日期，且当前日期 - 碎片所属日期 ≤ 7 天 | 每日提醒 | 可与新碎片整合 |
| 已过期（超过7天） | 当前日期 - 碎片所属日期 > 7 天 | 不再提醒 | 不可整合，只读归档 |
| 已完成 | 当天已完成写作 | 不提醒 | 该日期不可编辑已有碎片、不可重新生成叙事、不可添加新碎片、不可删除（已完成状态意味着写作已闭环）；若需补充内容，只能在**其他日期**（次日或之后）创建新碎片，不可向已完成日期追加 |

- 跨天未完成的碎片保留 7 天，超过 7 天自动归档
- 次日进入碎片日记时，提示"你有 X 个未完成的碎片，要继续吗？"
- 跨天碎片可以与新碎片一起整合（详见 [6.4 跨天碎片整合](#64-跨天碎片整合)）
- **超过 7 天的碎片**：不再主动提醒，用户主动查看时显示为只读归档状态，不可整合，但仍可删除（需二次确认）
- **删除权限规则**（按优先级从高到低）：
  - **第一优先级**：「已完成」状态（`completed=true`）→ 任何情况下不可删除（保持叙事完整性），**无论是否超过 7 天**
  - **第二优先级**：「已过期/超过 7 天」状态（`completed=false` 且当前日期-碎片所属日期>7天）→ 可删除（需二次确认）
  - **第三优先级**：其他状态（进行中/未完成，`completed=false`） → 可删除（需二次确认）
  - **优先级规则**：当同一日期同时满足多个条件时（如已完成且超过7天），按第一优先级处理，即不可删除。第二优先级仅适用于未完成状态（`completed=false`）的已过期碎片
- **归档时间计算**：自然日相加，非精确小时计算。例如：碎片所属日期为 5月25日（周一），则归档日期为 6月1日（周一，即 5月25日 + 7 天）。判断公式：`当前日期 - 碎片所属日期 > 7 天`（严格大于，第 7 天仍可操作，第 8 天起归档）

**状态转换规则：**
- **转换粒度**：状态转换按**日期级别**执行，非碎片级别。`completed` 是日期级别的属性
- **「当日」定义**：「完成今天的碎片」中的"今天"指**物理日期**（用户当前操作的日期）。触发写作时，物理日期的碎片参与整合。若用户选择跨天整合，则参与整合的所有日期均标记为已完成（详见 [6.4 跨天碎片整合](#64-跨天碎片整合)）。**补录场景**：碎片归属于原始日期，但「完成今天的碎片」仍以物理日期为准。例如：用户在 6 月 1 日补录 5 月 29 日的碎片，点击"完成今天的碎片"时触发的是 6 月 1 日（物理日期）的写作流程
- 进行中 → 已完成：用户点击"完成今天的碎片"触发写作后，该日期的 `completed` 设为 `true`，`writing_context` 被填充
- 已完成 → 进行中：**不可逆**，已完成状态不可回退到进行中状态
- 未完成（7天内）→ 已过期：超过 7 天自动转换，碎片归档为只读状态
- **转换时机**：状态变更在用户触发写作或日期变更时自动执行
- **跨天整合时的状态**：参与整合的**所有日期**（仅限未完成状态的日期，不包括已完成日期）均标记为已完成（详见 [6.4 跨天碎片整合](#64-跨天碎片整合)）

### 3.7 碎片数量限制

- **单日上限**：10 个碎片
- **空内容碎片计入上限**：空内容碎片也占用 10 个上限名额（防止滥用）
- **超出处理**：提示用户"今天的碎片已达上限，建议先完成写作"
- **最低要求**：至少 1 个有内容的碎片才能触发写作
- **上限后继续输入**：用户可选择"删除旧碎片腾出空间"或"先完成写作"
- **已完成状态的上限处理**：已完成日期不允许再添加新碎片（已完成状态意味着写作已闭环，见 [3.6 已完成状态](#36-碎片生命周期)）

## 4. 用户流程

### 4.1 碎片输入流程

**补录入口**：如需补录历史日期碎片，点击「补录」按钮选择目标日期（最近 30 天内），进入补录模式后流程与普通输入一致。

**触发写作的两种方式：**
1. **主动触发**：用户点击"完成今天的碎片"
   - 若存在历史未完成碎片（7天内），弹窗询问"是否包含历史碎片？"，用户可选择"仅完成今日"或"整合历史碎片"
   - 若无历史未完成碎片，直接触发今日碎片的写作
   - **「仅完成今日」后的上限处理**：若当日已达 10 个碎片上限，提示"已达今日碎片上限，请删除旧碎片或完成当前写作"。用户选择"完成写作"时，系统先检查是否有有效内容（至少 1 个有内容的碎片），若有则正常触发写作流程（上限不影响写作触发，仅限制新增碎片），若无则提示"所有碎片均为空内容，无法生成叙事"
2. **被动触发**：当日碎片数量达到上限（10 个）时，系统自动提示
   ```
   系统：今天的碎片已达上限（10个），是否完成写作？
       [完成写作] [删除旧碎片] [继续查看]
   ```
   - 选择"完成写作"：触发写作流程（同主动触发）
   - 选择"删除旧碎片"：进入碎片列表，用户选择删除哪个碎片
   - 选择"继续查看"：关闭提示，用户可查看已有碎片但无法新增

**继续未完成碎片的判断：**
- 进入碎片日记时，系统检测是否存在 `completed=false` 的碎片
- 今日有未完成碎片 → 显示"你有 X 个未完成的碎片，要继续吗？"
- 历史有未完成碎片（7天内）→ 同上提示
- 仅历史有已过期碎片 → 仅显示只读归档列表

### 4.2 写作自由度说明

#### 4.2.1 来源标签（origin）

来源标签是**必选**的，用于标识碎片的触发来源：

- **user** — 用户主动发起的消息（"我给ta发了..."）
- **crush** — 来自 crush 的消息（"ta给我发了..."）
- **ambient** — 环境触发（"看到ta的动态..."、"在XX遇到ta..."）

#### 4.2.2 情绪标签（mood）

情绪标签用于标识碎片的情绪状态：

- **positive** — 开心、期待、温暖
- **negative** — 难过、失落、在意
- **neutral** — 平静、日常、无特别
- **mixed** — 复杂、矛盾、说不清

**必选/可选规则：**
- Raw 模式：**可选**，用户可跳过
- Guided 模式：**可选**，系统推荐后用户可接受、修改或跳过
- Themed 模式：**必选**
- Blind 模式：**必选**

**"跳过" vs "neutral" 的语义区别：**
- 用户主动选择 `neutral`：表示"我明确知道这是平静的/日常的"
- 用户跳过情绪标签：表示"我不确定/不想定义情绪"
- 系统处理：跳过时 Prompt 中不添加情绪修饰，neutral 时添加"日常/平静"修饰

**混合情绪（mixed）的细分（可选）：**
- 用户选择 `mixed` 后，下方显示"细分情绪"按钮
- 点击后展开输入框，提示"哪些事情让你开心？哪些事情让你失落？"
- 用户填写或跳过
- 不点细分时，直接使用 `mixed` 情绪
- 细分结果用于生成更精准的 Prompt，如"心情复杂，既开心又失落"
- **适用范围**：所有模式（Raw/Guided/Themed/Blind）选择 `mixed` 时均可使用细分功能

#### 4.2.3 Raw 模式

最自由的入口。

- **来源标签**：必选（user / crush / ambient）
- **情绪标签**：可选（用户可以选择，也可以跳过）
- **内容**：用户自由输入，无引导提示
- **适用场景**：用户有明确想法，不需要引导

#### 4.2.4 Guided 模式

半结构化入口，提供方向引导。

- **来源标签**：必选
- **情绪标签**：可选，系统根据方向自动推荐，用户可接受、修改或跳过
- **方向**：从三个预设方向中选择一个（每日限选一个方向，不可自定义）
- **适用场景**：用户有模糊想法，需要一些引导

**每日方向限制规则：**
> 每个自然日只能选择一个方向，选择后当日不可更改。当日多次使用 Guided 模式时，方向保持不变。示例：用户上午选择"轻松的"方向，下午再次使用 Guided 模式时，方向自动设为"轻松的"，不可更改。

**方向重置规则：**
- **同一天内**：关闭页面后再次进入，方向保持不变（从日期配置中读取）
- **跨天重置**：每日 00:00（用户本地时间）自动重置方向，用户需重新选择
- **UI 提示**：使用 Guided 模式时，若当日已选择方向，界面显示当前方向（如"今日方向：轻松的"）

**情绪推荐与跳过规则：**
- 系统根据方向自动推荐情绪（如"轻松的"→positive）
- 推荐情绪**可以跳过**，跳过视为用户主动放弃情绪修饰
- 跳过后 Prompt 仅使用方向引导，不添加情绪词
- 示例：Guided+轻松的+跳过 → "记录一些日常小事"（不包含"开心"等情绪词）

**跳过情绪的处理：**
- 若用户跳过推荐情绪，Prompt 中不添加情绪修饰
- 等同于 Raw 模式跳过情绪的处理方式

**方向选项（固定三选一）：**
- 轻松的（"记录一些日常小事"）
- 有些在意的（"说说那些让你在意的事"）
- 想深入的（"展开聊聊这个话题"）

**方向→情绪推荐映射：**

| 方向 | 推荐情绪 | 推荐理由 |
|------|----------|----------|
| 轻松的 | positive | 轻松通常对应开心、愉快的情绪 |
| 有些在意的 | negative | 在意通常对应关注、在意的情绪 |
| 想深入的 | mixed | 深入探讨可能涉及复杂情绪 |

**每日限制说明：**
- 每个自然日选择一种方向，选择后当日不可更改
- 当日可多次使用 Guided 模式，但方向保持不变
- 次日重置，可重新选择方向
- **时间基准**：使用用户本地时间（浏览器/客户端时区），每日 00:00 重置
- **跨时区处理**：若用户在时区变更（如出差）后使用，按新时区的日期判断是否重置

#### 4.2.5 Themed 模式

主题限定入口，围绕特定主题写作。

- **来源标签**：必选
- **情绪标签**：必选
- **主题**：从预设主题中选择（单选，必选）
- **适用场景**：用户想围绕某个主题写

**选择流程（四个步骤，前三步必须选择，不可跳过）：**
1. 选择来源（必选）
2. 选择情绪（必选）
3. 选择主题（必选）
4. 输入内容（必选）

**情绪必选的原因：**
- 主题（场景）通常与情绪有对应关系
- 系统会根据主题+情绪组合生成更精准的 Prompt
- 示例：「争吵/误会」主题默认对应负面情绪，「和好/道歉」默认对应正面情绪
- 用户仍可自定义选择其他情绪，系统会根据组合调整 Prompt

**预设主题列表：**

| 主题 | 说明 | 示例场景 |
|------|------|----------|
| 工作/学习 | 与工作、学习相关的互动 | "ta在工作时给我发消息" |
| 生活日常 | 日常生活中的小事 | "ta分享了今天吃了什么" |
| 约会/出行 | 约会、外出相关的场景 | "今天和ta一起去了..." |
| 情感交流 | 深入的情感对话 | "ta说了让我在意的话" |
| 兴趣爱好 | 与兴趣、爱好相关 | "ta推荐了一首歌" |
| 节日/纪念日 | 节日、纪念日相关 | "ta在生日时..." |
| 争吵/误会 | 冲突、误会相关 | "我们因为XX吵了一架" |
| 和好/道歉 | 和好、道歉相关 | "ta主动来找我和好" |

**与 Guided 模式的区别：**
- Guided 模式的「方向」是情绪导向（轻松的/在意的/想深入的）
- Themed 模式的「主题」是场景导向（工作/约会/情感交流等）
- 用户可同时选择主题和情绪，获得更精准的写作引导

#### 4.2.6 Blind 模式

盲写入口，写作过程中隐藏对话历史，完成后展示对比。

- **来源标签**：必选
- **情绪标签**：必选
- **内容**：用户自由输入（10-500 字，最低 10 字以确保匹配效果）
- **特殊机制**：
  - **输入阶段**：界面只显示输入框，隐藏之前的对话记录和 crush 回复
  - **临时查看**：提供「暂看」按钮，点击后可临时查看对话历史，输入内容不丢失
  - **暂看按钮与编辑状态**：「暂看」按钮在任何状态下可用，点击后显示对话历史浮层（半模态遮罩），底层编辑内容保留不变，浮层显示时用户不能同时操作输入框。浮层底部提供「返回编辑」按钮（与关闭按钮并列），点击后关闭浮层并自动聚焦到输入框，用户可继续编辑
  - **完成方式**：用"写完了"按钮替代发送按钮
  - **回复来源**：仅从 crush 角色档案中匹配（不访问历史消息），根据用户输入内容匹配最相关的回复
  - **回复数量**：默认展示 1 条匹配回复，最多展示 3 条
  - **对比展示**：完成后同时显示用户原文和 crush 回复，供用户对比
- **适用场景**：用户想先自由表达，再看 crush 的回应

**隐私边界说明：**
- Blind 模式**不访问**对话历史记录，仅使用 crush 角色档案中的静态信息
- 匹配逻辑基于关键词和语义相似度，不涉及消息时间线
- 用户可随时关闭对比展示，只保留自己的原文
- **两个功能的关系**：「匹配回复」和「冲突检测」是两个独立功能，都不访问历史消息。匹配回复基于 crush 档案生成回复建议；冲突检测基于 crush 档案检测输入内容的一致性

**写作质量验证：**
- 写作前检测用户输入内容与 crush 档案的一致性
- 如存在明显冲突（如用户描述了 crush 档案中不存在的行为模式），提示用户"这与 {crush_name} 的设定可能不一致，是否继续？"
- 用户可选择"以档案为准"或"以用户输入为准"
- **选择"以用户输入为准"后的处理**：系统按用户输入内容生成叙事，但叙事中会避免与档案明显矛盾的具体表述（如将具体行为改为更通用的描述）

**匹配规则细节：**
- **匹配算法**：基于关键词 + 语义相似度双重匹配
- **相似度阈值**：>60% 才展示（可调整范围：50%-80%）
- **匹配上限**：默认 1 条，最多 3 条（用户可在 `fragment_settings.md` 配置文件中调整 `blind_match_limit` 参数）
- **无匹配时**：显示"暂无相关回复"，或根据 crush 档案生成默认回复
- **匹配范围**：仅从 crush 角色档案中匹配（性格特征、常见回复、行为模式等）

**匹配字段优先级：**
1. **常见回复（crush_replies）**：直接匹配相似内容
2. **性格特征（personality）**：根据性格调整匹配权重
3. **行为模式（behavior_patterns）**：匹配用户输入中的行为描述

**相似度计算：**
- 关键词匹配：30% 权重
- 语义相似度：70% 权重（基于角色设定中的语气/风格）
- 阈值可调整范围：50%-80%（用户可在设置中选择）

### 4.3 碎片内容输入

#### 4.3.1 内容输入流程

用户输入碎片内容的流程：

1. **输入内容** — 用户输入文字（可选，长度 5-500 字）
2. **标签推荐** — 系统根据内容自动推荐环境标签和行为标签（可选）
3. **确认提交** — 用户确认，碎片记录完成

**提交时的标签状态：**
- 若推荐正在加载，提交时直接保存（不等待推荐结果）
- 推荐完成后若用户已提交，不影响已保存的碎片
- 用户可在"编辑碎片"时查看和修改推荐标签
- **规则**：提交时只保存用户已明确接受/选择的标签，正在加载或待确认的推荐不保存

**内容规范：**
- 最小长度：5 字（过短无法生成有意义的 Prompt）
- 最大长度：500 字（避免 Prompt 过长）
- 纯表情/符号：系统提示"请补充文字描述，表情符号无法单独生成叙事"
- 空内容：允许保存，但系统会提示"建议补充一些描述，让叙事更丰富"
- **空内容提示**：碎片记录成功后显示"碎片已记录 ✓（空内容不参与写作生成）"

#### 4.3.2 标签推荐机制

**环境标签推荐：**
- 从 crush 角色档案的环境信息中提取
- 根据用户输入内容匹配相关环境
- 用户可选择接受或忽略推荐

**行为标签推荐：**
- 从 crush 角色档案的行为模式中提取
- 根据用户输入内容匹配相关行为
- 用户可选择接受或忽略推荐

**推荐准确度与降级策略：**
- 推荐标签与用户输入的相关度低于 50% 时，不显示推荐
- 用户连续 3 次忽略推荐时，降低推荐频率（同一会话内累计）
- 降频后：推荐阈值从 50% 提高到 70%，仅显示高相关度推荐
- 恢复机制：用户主动接受 1 次推荐后，恢复正常推荐频率
- 推荐失败时，降级为不推荐，用户可手动添加标签

**降频规则详细说明：**
- **统计范围**：单次碎片输入会话（从输入内容到提交）
- **触发条件**：同一会话内连续 3 次忽略推荐
- **降频效果**：推荐阈值从 50% 提高到 70%
- **恢复条件**：用户主动接受 1 次推荐后，当次会话内推荐阈值立即从 70% 恢复到 50%，并正常触发下一次推荐
- **降频范围**：仅当前会话，下一次输入重新计数

**示例：**
```
用户输入："ta今天发了一个可爱的表情包"
系统推荐：
  环境标签：[工作]（相关度 60%，显示）
  行为标签：[可爱]（相关度 85%，显示）
用户选择：接受 [可爱]，忽略 [工作]
```

#### 4.3.3 碎片编辑与删除

用户可以对已输入的碎片进行管理：

**编辑操作：**
- 查看碎片列表：显示当天所有碎片
- 编辑单个碎片：修改来源、情绪、内容、标签
- 删除单个碎片：确认后删除
- 撤销最近输入：删除最后输入的碎片

**操作限制：**
- 已完成写作的日期，碎片不可编辑（只读）
- 删除碎片后不可恢复（需二次确认）
- 编辑界面过程中，不允许切换写作模式（需先保存或取消当前编辑）
- 退出编辑时检测未保存变更，弹出确认框"有未保存的变更，是否保存？"

**碎片编辑与写作状态：**
- **未触发写作**（`completed=false`，`writing_context` 为空）：碎片可自由编辑（来源、情绪、内容、标签均可修改）
- **已触发写作但未确认完成**（`completed=false`，`writing_context` 已有内容，叙事已生成但用户未点击"完成"）：碎片内容只读，来源、情绪、内容、标签不可修改，仅允许「重新生成叙事」按钮，重新调用 day 模块生成，覆盖原有叙事文本（需用户确认）
- **已完成写作**（`completed=true`）：全部只读，**不可重新生成叙事**，**不可删除**（任何情况下不可删除，无论是否超过 7 天，保持叙事完整性），仅可查看
  - **设计说明**：已完成状态的叙事是用户确认的最终版本，允许重新生成会破坏叙事的确定性。如需优化叙事，用户可在新日期创建碎片并重新写作

**重新生成叙事的处理范围：**
- 重新生成时，基于**当日所有碎片**重新整合生成叙事
- 若当日有新增碎片（在首次生成后添加），新增碎片会参与重新生成
- 用户无法手动排除某些碎片参与重新生成
- 重新生成会**覆盖**原有 `writing_context` 内容，需用户确认
- **失败时的处理**：重新生成前先备份原 `writing_context`，若生成失败（如 API 错误、超时），恢复原内容，并提示用户"生成失败，请重试"

**删除二次确认：**
```
系统：确认删除此碎片？
    碎片内容：{content}
    删除后不可恢复。
    [确认删除] [取消]
```

**批量删除限制：**
- 每次最多删除 1 个碎片（防止误操作）
- 如需批量删除，需逐个确认

**已完成日期的特殊处理：**
- 碎片只读，不可编辑
- 不可重新生成叙事（已完成状态意味着写作已闭环）
- 新增碎片不参与已完成叙事

#### 4.3.4 本地记录存储

碎片记录存储在 `crushes/{slug}/fragments/` 目录下，按日期组织。详见 [3.4 碎片存储](#34-碎片存储)。

## 5. 写作触发机制

### 5.1 碎片触发写作

当用户完成碎片输入后，系统根据碎片内容触发写作：

```
碎片输入完成
    │
    ▼
┌─────────────────────────────────────────┐
│          整合碎片为写作上下文             │
│  （来源 + 情绪 + 内容 → 叙事素材）       │
└─────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────┐
│          生成写作 Prompt                 │
│  （基于 day 写作原则）                   │
└─────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────┐
│          执行写作                        │
│  （调用 day 模块生成叙事）               │
└─────────────────────────────────────────┘
```

### 5.2 Prompt 生成逻辑

系统根据碎片的来源和情绪标签，生成对应的写作 Prompt：

**Prompt 生成公式：**
```
prompt = base_prompt(origin) + mood_modifier(mood) + context(content)
```

**各模式的 Prompt 处理：**

| 模式 | 来源方向 | 情绪标签 | Prompt 生成逻辑 |
|------|----------|----------|-----------------|
| Raw | 必选 | 可选 | 有情绪时：`base_prompt(origin) + mood_modifier(mood)`；无情绪时：`base_prompt(origin)` |
| Guided | 必选（方向） | 可选（系统推荐） | `direction_prompt(direction) + [mood_modifier(mood)]` |
| Themed | 必选 | 必选 | `theme_prompt(theme) + base_prompt(origin) + mood_modifier(mood)` |
| Blind | 必选 | 必选 | `base_prompt(origin) + mood_modifier(mood)` + 盲写特殊处理 |

**Raw 模式下情绪标签为空的处理：**
- 当用户跳过情绪标签时，系统不添加情绪修饰
- Prompt 仅使用来源方向的基础 Prompt
- 与选择 `neutral` 的区别：neutral 会添加"日常/平静"修饰，跳过则不添加任何情绪修饰

**Guided 模式下情绪标签为空的处理：**
- 当用户跳过情绪标签时，系统不添加情绪修饰
- Prompt 仅使用方向 Prompt：`direction_prompt(direction)`
- 与 Raw 模式跳过情绪的区别：Guided 模式有方向约束（如"轻松的"、"浪漫的"），方向本身提供叙事基调，无需额外情绪修饰

**示例 Prompt：**
- 用户 + positive → "记录一下，今天我给ta发了什么"
- crush + negative → "ta今天说了什么让你在意的话？"
- ambient + mixed → "在XX时，看到ta的XX，心情复杂"
- user + 跳过 → "记录一下，今天我给ta发了什么"

**完整 Prompt 矩阵（3来源 × 4情绪 + 跳过 = 13种组合）：**

| 来源 \ 情绪 | positive | negative | neutral | mixed | 跳过 |
|-------------|----------|----------|---------|-------|------|
| user | "记录一下，今天我给ta发了什么" | "今天我给ta发了什么，让ta在意了？" | "今天我给ta发了什么？" | "今天我给ta发了什么，心情复杂" | "记录一下，今天我给ta发了什么" |
| crush | "ta今天说了什么让你开心的话？" | "ta今天说了什么让你在意的话？" | "ta今天说了什么？" | "ta今天说了什么，心情复杂" | "ta今天说了什么？" |
| ambient | "在【环境】时，看到ta的【行为】，感到开心" | "在【环境】时，看到ta的【行为】，感到在意" | "在【环境】时，看到ta的【行为】" | "在【环境】时，看到ta的【行为】，心情复杂" | "在【环境】时，看到ta的【行为】" |

**占位符说明：**
- **"【环境】"**：根据用户输入的环境标签填充（如"工作时"、"下班路上"、"在公园"）
- **"【行为】"**：根据用户输入的行为标签填充（如"发了一个表情包"、"回了一个嗯"）
- **无标签信息时**：使用"某个时刻"或直接省略，如"看到ta的动态，感到开心"
- **内容为空时**：Prompt 仅使用来源+情绪方向，不包含具体内容描述

**占位符填充优先级：**
1. 用户选择的 `env_tags`
2. 用户输入 `content` 中通过 NLP 提取的地点词
3. crush 角色档案中的常去地点
4. 默认值："某个时刻"

## 6. 碎片整合逻辑

### 6.1 单碎片整合

当用户只输入一个碎片时，直接使用该碎片作为写作上下文。

### 6.2 多碎片整合

当用户输入多个碎片时，系统按以下规则整合：

**整合规则：**
1. **同日整合** — 同一天的碎片合并为一个写作上下文
2. **来源合并** — 所有碎片的来源都参与 Prompt 生成，按碎片时间戳（`time` 字段）升序排列
3. **情绪处理** — 多个碎片的情绪按以下规则处理：
   - 情绪相同：使用该情绪
   - 情绪不同：使用 `mixed`，或根据以下规则判断主导情绪：
     - 数量多的情绪优先
     - 数量相同时，negative 优先（出于叙事张力考虑）
     - 用户明确指定时以用户指定为准
   - 有情绪 + 跳过：以有情绪的碎片统计主导情绪。若有情绪碎片情绪一致，使用该情绪；若情绪不一致，遵循「情绪不同」规则判断主导情绪或使用 mixed
   - 单个有效情绪：若只有一个碎片有情绪（其他都跳过），直接使用该情绪，无需判断主导
   - 全是跳过：Prompt 中不添加情绪修饰
   - **边界情况**：部分碎片情绪为 null（跳过）+ 部分碎片情绪有效时，忽略 null，按「情绪相同」或「情绪不同」规则处理
4. **内容拼接** — 多个碎片的内容按时间顺序拼接，使用自然语言连接符
5. **长度控制** — 整合后内容超过 1000 字时，自动压缩或摘要

**示例：**
```
碎片1：user + positive + "ta发了一个表情包"
碎片2：crush + neutral + "ta回了一个"嗯""
整合后：
  来源：user + crush（合并）
  情绪：mixed（positive + neutral → mixed）
  内容："ta发了一个表情包，然后ta回了一个"嗯""
```

### 6.3 碎片与角色档案的关联

碎片整合时，系统会关联 crush 角色档案中的信息：

- **环境信息** — 碎片中的环境标签与档案中的环境信息匹配
- **行为模式** — 碎片中的行为标签与档案中的行为模式匹配
- **性格特征** — 根据档案中的性格特征，调整叙事风格

### 6.4 跨天碎片整合

当用户选择继续未完成的碎片时：

**整合前置条件：**
- 系统自动过滤掉超过 7 天的碎片，用户**只能选择近 7 天内的日期**进行整合
- 已归档日期（超过 7 天）不会出现在可选列表中，用户无法选择
- **UI 反馈**：若用户进入整合页面时存在已归档日期，页面底部提示"部分历史碎片已归档，仅显示近 7 天内的碎片"
- **补录碎片整合规则**：补录碎片参与整合时，以**原始日期**判断是否在 7 天内，而非提交日期。整合后，补录碎片的原始日期和物理日期（用户当前操作日期）均标记为已完成（`completed=true`）

**日期选择机制：**
- 系统自动列出近 7 天内有未完成碎片的日期（`completed=false`）
- 默认选中当前日期，用户可勾选其他日期（多选）
- 每个日期显示碎片数量预览（如"周二 · 3个碎片"）
- 已归档日期（超过 7 天）灰显，不可勾选
- **已完成日期**（`completed=true`）不出现在可选列表中（已完成状态不可参与新整合）

**整合规则：**
- 仅 7 天内的碎片可参与整合
- 来源、情绪、内容的整合逻辑同 [6.2 多碎片整合](#62-多碎片整合)
- **内容排列顺序**：按时间顺序拼接（历史碎片在前，当前日期碎片在后），与 6.2 规则一致
- **Prompt 权重**：当前日期碎片的内容作为叙事重心，历史碎片作为补充背景
- **长度超限的压缩策略**：跨天整合时若总内容超过 1000 字，优先保留当前日期碎片的核心信息，历史碎片作为背景摘要

**整合后的状态转换：**
- 参与整合的**所有日期**（仅限未完成状态的日期，不包括已完成日期）均标记为已完成
- `completed` 设为 `true`，`writing_context` 填充生成的叙事内容
- 示例：用户整合周二+周四的碎片，周二和周四的 `completed` 均设为 `true`

**跨天整合的确认与撤销：**
- **确认流程**：用户选择日期后，系统显示整合预览（参与的日期、碎片数量、预计内容长度），用户需点击「确认整合」才执行
- **撤销机制**：整合完成后，用户可在当日内撤销整合（将参与的日期重置为 `completed=false`），撤销后可重新选择日期整合
- **撤销限制**：仅限当日内撤销，跨天后不可撤销（已完成状态不可逆）
- **物理日期的特殊处理**：跨天整合包含物理日期（用户当前操作的日期）时，整合后物理日期标记为已完成，用户无法在该日期继续添加新碎片。如需继续输入，用户需在次日创建新碎片

**整合后新增碎片的处理：**
- 跨天整合完成后，若用户在物理日期（用户操作的当天）新增碎片，这些碎片属于**物理日期**（如用户在5月30日操作，则新碎片属于5月30日），不归属于已整合的历史日期（如5月25日或5月29日）
- 已完成的历史日期不允许添加新碎片（见 [3.6 已完成状态](#36-碎片生命周期)）
- **示例**：用户在5月29日整合了5月25日和5月29日的碎片，整合后5月25日和5月29日均标记为已完成。用户在5月30日（物理日期）新增的碎片属于5月30日，而非已完成的5月25日或5月29日

**示例：**
```
周二碎片：user + positive + "ta发了一个表情包"
周四碎片：crush + neutral + "ta回了一个"嗯""
整合后：
  来源：user + crush
  情绪：mixed
  内容："ta发了一个表情包（周二），然后ta回了一个"嗯""（周四）"
```

## 9. 边界情况与异常处理

### 9.1 输入边界

| 场景 | 处理方式 |
|------|----------|
| 内容为空 | 允许，提示"建议补充描述" |
| 内容 < 5 字（其他模式） | 提示"内容太短，请补充描述" |
| 内容 > 500 字 | 提示"内容过长，请精简到500字以内" |
| 纯表情/符号 | 提示"请补充文字描述，表情符号无法单独生成叙事" |
| 单日碎片 > 10 个 | 提示"今天的碎片已达上限，建议先完成写作" |
| Blind 模式内容 < 10 字 | 提示"盲写模式至少需要 10 字"（Blind 模式：10-500 字，其他模式：5-500 字） |

### 9.2 情绪标签边界

| 场景 | 处理方式 |
|------|----------|
| Raw 模式跳过情绪 | Prompt 中不添加情绪修饰 |
| Guided 模式跳过情绪 | Prompt 仅使用方向引导，不添加情绪词（与 4.2.4 一致） |
| 多碎片情绪冲突 | 使用 mixed，或根据内容判断主导情绪 |
| 跳过 vs neutral | 跳过：无修饰；neutral：添加"日常/平静"修饰 |

### 9.3 来源标签边界

| 场景 | 处理方式 |
|------|----------|
| 多碎片来源不同 | 合并所有来源，按输入顺序排列 |
| 切换 Crush 时编辑中 | 自动保存到原 Crush |
| 来源标签为空 | 不允许，来源是必选的 |

### 9.4 跨天碎片边界

| 场景 | 处理方式 |
|------|----------|
| 跨天碎片整合（7天内） | 保留所有碎片，可与新碎片合并为一个写作上下文 |
| 超过 7 天未完成 | 自动归档，不再提醒，不可整合 |
| 归档后想继续 | 提示"该日期碎片已归档，只读查看，无法继续" |
| 归档后想整合 | 不允许，需创建新日期的碎片 |

### 9.5 写作失败处理

| 场景 | 处理方式 |
|------|----------|
| API 调用失败 | 提示"写作生成失败，请重试"，碎片保留 |
| 超时 | 提示"请求超时，请重试"，碎片保留 |
| 内容过长导致失败 | 自动压缩内容后重试 |

### 9.6 标签推荐边界

| 场景 | 处理方式 |
|------|----------|
| 推荐不相关 | 相关度 < 50% 时不显示推荐 |
| 连续忽略推荐 | 连续 3 次忽略后降低推荐频率 |
| 推荐失败 | 降级为不推荐，用户可手动添加 |

### 9.7 时间戳处理

| 场景 | 处理方式 |
|------|----------|
| `time` 为空 | 系统自动使用当前时间 |
| 同一秒输入多个碎片 | ID 使用随机后缀区分（4位十六进制），按输入顺序排列 |
| 补录历史碎片 | 允许补录最近 30 天内的碎片，用户可手动设置日期和时间 |
| 补录超过 30 天 | 提示"只能补录最近 30 天的碎片" |
| 补录的碎片归档 | 补录的碎片同样受 7 天归档限制（以原始日期计算） |
| 补录碎片 ID | 使用**原始日期**生成 ID（`frag_{原始日期YYYYMMDD}_{HHMMSS}_{4位随机}`），确保排序正确 |

**补录碎片归档规则详细说明：**
- **归档时间** = 原始日期 + 7 天（非补录日期）
- **UI 显示**：补录碎片标注原始日期和补录日期，如"周一 · 补录于5月29日"
- **示例**：用户在5月29日（周五）补录了5月25日（周一）的碎片，UI显示"周一 · 补录于5月29日"，归档时间为6月1日（周一+7天）
- **补录定义**：在非当日创建的历史碎片
- **补录碎片的 direction 处理**：补录 guided 模式碎片时，direction 使用补录当日的方向（日期级别属性）。若补录当日未选择方向，系统提示用户先选择方向
- **补录限制**：仅允许补录未归档的碎片（原始日期在 7 天内）
- **日期选择范围**：日期选择器显示最近 30 天的日期，但已归档的日期（原始日期超过 7 天）灰显不可选
- **已过期碎片的处理**：若当前日期-原始日期 > 7 天（已过期），不允许补录，提示"该日期碎片已归档，无法补录"
- **补录与归档的关系**：补录操作在归档之前进行。补录后的碎片按照原始日期计算归档时间（原始日期+7天）。若补录时当前日期-原始日期 > 7 天，该碎片已归档，不允许补录
- **与跨天整合的关系**：补录碎片参与跨天整合时，同样以"当前日期-原始日期 ≤ 7 天"为判断标准。若补录时已超过 7 天，该碎片不可补录，也不可参与跨天整合
- **拦截时机**：用户点击「补录」按钮时，日期选择器自动过滤掉不可补录的日期（超过 30 天或已归档），用户无法选择这些日期
- **补录数量限制**：补录碎片受目标日期的单日上限限制（最多 10 个），若目标日期已有 10 个碎片，则无法补录
- **时间戳字段**：`created_at` 和 `updated_at` 使用**补录时的实际时间**（如 2026-05-29T14:30:00），原始日期仅用于归档计算和 ID 生成

### 9.8 并发写入处理

| 场景 | 处理方式 |
|------|----------|
| 多客户端同时输入 | ID 使用 `frag_{YYYYMMDD}_{HHMMSS}_{4位随机}` 保证唯一性 |
| 快速连续点击"完成" | 防抖处理：2 秒内重复点击忽略 |
| 文件写入冲突 | 使用文件锁机制，写入前检查文件版本 |
| 编辑时碎片被删除 | 检查碎片是否存在，不存在则提示"碎片不存在或已被删除" |
| 编辑时碎片被修改 | 乐观锁检查（使用 `updated_at` 时间戳判断），版本冲突则提示"碎片已被其他客户端修改，[重新加载] [覆盖保存]" |

### 9.9 编辑时模式切换

| 场景 | 处理方式 |
|------|----------|
| 编辑界面过程中切换模式 | 不允许，提示"请先保存或取消当前编辑" |
| 已选方向/主题的处理 | 保存后切换，方向/主题保留到下次使用 |
| 编辑过程中收到过期提醒 | 暂停编辑，弹出提醒框"碎片即将过期，是否继续编辑？" |
| 编辑过程中碎片被其他客户端修改 | 显示"碎片已被其他设备修改，当前编辑内容将丢失，是否重新加载？" |

### 9.10 空内容处理

| 场景 | 处理方式 |
|------|----------|
| 空内容碎片能否保存 | 允许保存，计入当日碎片数量上限 |
| 空内容碎片能否触发写作 | 不能，提示"至少需要 1 个有内容的碎片才能生成叙事" |
| 多碎片中部分为空 | 整合时跳过空内容碎片，使用有内容的碎片生成叙事 |
| 整合确认页显示 | 显示"参与写作的碎片"和"跳过的碎片（空内容）" |
| 空内容碎片状态 | 标注"（空内容，不参与写作）" |
| 当日 10 个碎片全为空内容 | 提示"所有碎片均为空内容，无法生成叙事。请补充描述或删除空碎片后重试。" |

### 9.11 写作完成后补充

| 场景 | 处理方式 |
|------|----------|
| 已完成写作后想补充内容 | 提示"该日期已完成写作，无法补充"（指修改已有碎片内容） |
| 已完成写作后想添加新碎片 | 不允许（已完成状态意味着写作已闭环，见 [3.6 已完成状态](#36-碎片生命周期)） |
| 想重新打开已完成日期 | 不允许，需创建新日期的碎片 |
