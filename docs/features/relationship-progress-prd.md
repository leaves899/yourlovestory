## 当前实现摘要

当前实现使用五阶段模型：陌生人（`stranger`）、认识（`acquaintance`）、暧昧（`flirting`）、表白（`confession`）和热恋（`passion`），定义位于 `src/shared/relationship/models.ts`，阶段 Prompt 位于 `src/shared/relationship/phase_prompts.ts`。关系规则通过兼容 Day 叙事使用，并由角色 `.intimate_config` 约束亲密内容。

关系进度页面是兼容入口，长篇工作台是当前产品主线。独立 `SKILL.md` 不再作为运行时入口，旧 Crush 和 Fragment 数据只通过一次性导入进入工作台，分别映射为 Character 和 SourceMaterial，导入后不持续同步。

下文保留早期四阶段方案，供理解历史决策和迁移背景使用；实现或新增功能请以 [ADR-0005](../adr/0005-workbench-priority-and-legacy-import.md) 与 [CONTEXT.md](../../CONTEXT.md) 为准。

## 1. 背景与目标

### 问题

yourcrush 当前的角色档案是静态的——创建后关系状态不会自然演进。用户缺乏：

- **长期目标感：** 不知道"写到什么程度算成功"
- **成长反馈：** 没有可视化的进展指标
- **阶段激励：** 所有阶段使用相同的写作模板和 AI 能力

### 目标

将暗恋过程游戏化，设计关系阶段系统，让用户感受到"关系在推进"，并通过阶段解锁机制提供持续动力。

### 核心指标

| 指标 | 目标值 | 衡量方式 |
|------|--------|---------|
| 30日留存 | 提升 25% | 对比上线前后 |
| 平均创作次数/周 | ≥3 次 | 统计 narrative/ 目录 |
| 阶段推进率 | ≥60% 用户进入第二阶段 | 统计 progress.md 变更 |

## 2. 关系阶段设计

### 2.1 阶段定义

```
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│   Phase 0      Phase 1      Phase 2      Phase 3      Phase 4 │
│   ────────     ────────     ────────     ────────     ─────── │
│   陌生人   →   认识    →    暧昧    →    表白    →    热恋    │
│   Stranger      Acquaintance  Flirting     Confession   Passion │
│                                                               │
│   [当前默认]   [解锁互动]   [解锁亲密]   [用户确认]   [热恋]   │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 2.2 各阶段特征与解锁内容

| 阶段 | 关系特征 | 解锁能力 | 解锁模板 | 推进条件 |
|------|---------|---------|---------|---------|
| **Phase 0 陌生人** | 单方面关注，几乎没有交集 | 基础叙事、观察记录 | 观察日记、偶遇记录 | 完成角色创建 |
| **Phase 1 认识** | 有基本互动，知道彼此存在 | 互动叙事、对话生成 | 日常聊天、第一次对话 | ≥3 次互动叙事 + 用户确认 |
| **Phase 2 暧昧** | 频繁互动，有情感张力 | 情感分析、内心独白 | 约会叙事、情感波动 | ≥5 次暧昧叙事 + 用户确认 |
| **Phase 3 表白** | 明确关系，正式在一起 | 结局生成、关系回顾 | 表白场景、纪念日 | 用户主动触发 |
| **Phase 4 热恋** | 关系稳定且持续亲密 | 长期关系回顾、亲密叙事 | 纪念日、共同生活 | 用户主动确认 |

### 2.3 阶段过渡机制

**自动检测 + 用户确认** 模式：

1. AI 根据叙事内容自动检测阶段推进信号
2. 达到阈值时提示用户："你们的关系似乎进入新阶段了"
3. 用户确认后正式推进，解锁新内容
4. 用户也可手动调整阶段（尊重主观感受）

## 3. 用户场景

### 场景 A：阶段感知

```
用户完成第 4 次关于日常聊天的叙事
→ AI 检测到互动频率达到阈值
→ 提示："你们已经聊了好几次了，关系似乎从'认识'进入了'暧昧'阶段？
→ 用户确认
→ 解锁暧昧阶段的写作模板
→ 进度条更新
```

### 场景 B：阶段专属写作

```
用户处于暧昧阶段
→ 输入 /day 昨天和 TA 一起看了电影
→ AI 使用暧昧阶段的 prompt 模板
→ 生成带有情感张力的叙事（而非平淡的记录）
→ 自动提取暧昧信号，更新进度
```

### 场景 C：查看进度

```
用户输入 /progress
→ 显示当前阶段：暧昧（Phase 2/5）
→ 显示进度条：████████░░ 65%
→ 显示阶段统计：8 次互动，5 次暧昧
→ 显示下一阶段：表白（需更多情感积累）
```

### 场景 D：关系回顾

```
用户处于表白阶段
→ 输入 /review
→ AI 生成完整的关系时间线
→ 从第一次注意到现在的所有关键时刻
→ 生成"恋爱回忆录"草稿
```

## 4. 功能需求

### 4.1 /progress 命令（进度查看）

**输出内容：**

```markdown
## 关系进度

当前阶段：暧昧 Phase 2/5
进度：████████░░ 65%

### 阶段统计
- 总叙事数：12
- 互动叙事：8
- 暧昧信号：5
- 碎片记录：23

### 最近进展
- 5月28日：检测到暧昧信号（一起看电影）
- 5月25日：进入暧昧阶段

### 下一阶段
表白 Phase 3/5
需要：更多情感积累，或主动触发
输入 /confess 开始表白叙事
```

### 4.2 阶段检测逻辑

**检测信号（每条叙事完成后运行）：**

| 阶段 | 检测信号 | 权重 |
|------|---------|------|
| 0→1 | 有对话、知道名字、有联系方式 | 每项 +20 |
| 1→2 | 身体接触、深夜聊天、单独相处、送礼物 | 每项 +25 |
| 2→3 | 表白暗示、情感表白、亲密行为 | 每项 +30 |

**阈值设置：**

- 0→1：累积 ≥ 60 分
- 1→2：累积 ≥ 70 分
- 2→3：用户手动触发（不自动）

**用户确认弹窗：**

```
┌────────────────────────────────────────┐
│  关系阶段推进                           │
│                                        │
│  你们的关系从「认识」进入了「暧昧」阶段   │
│                                        │
│  基于最近的叙事内容：                    │
│  - 一起看了电影                         │
│  - 深夜聊了很久                         │
│                                        │
│  [确认推进]    [暂不推进]               │
│                                        │
└────────────────────────────────────────┘
```

### 4.3 阶段专属 Prompt 模板

**Phase 0 陌生人 - 观察者视角：**

```
你是一个细腻的观察者，记录用户对 TA 的单方面关注。
重点：外貌描写、环境细节、内心活动
语气：克制、细腻、略带忧伤
```

**Phase 1 认识 - 互动视角：**

```
你是一个善于捕捉互动细节的叙述者。
重点：对话内容、反应、小动作、初次互动的紧张感
语气：轻松、好奇、略带期待
```

**Phase 2 暧昧 - 情感视角：**

```
你是一个情感细腻的叙述者，擅长描写暧昧期的微妙张力。
重点：眼神交汇、肢体语言、未说出口的话、情感波动
语气：暧昧、期待、略带不安
```

**Phase 3 表白 - 结局视角：**

```
你是一个浪漫的故事讲述者，正在书写这段关系的高潮。
重点：情感爆发、告白场景、回应、关系确立
语气：热烈、真诚、充满希望
```

### 4.4 /confess 命令（表白叙事）

**触发条件：** 阶段 2（暧昧）或阶段 3（表白）

**功能：**

1. 引导用户描述表白场景
2. 生成表白叙事（可选多种风格：浪漫/真诚/搞笑）
3. 生成对方可能的回应（可选）
4. 标记关系阶段为"表白"
5. 解锁结局相关内容

**输出示例：**

```markdown
## 表白叙事

[用户描述的场景展开成完整叙事...]

---

关系阶段已更新：暧昧 → 表白

解锁新功能：
- /anniversary 纪念日叙事
- /review 关系回顾
- /future 未来畅想
```

### 4.5 /review 命令（关系回顾）

**触发条件：** 阶段 3（表白）

**功能：**

1. 读取所有历史叙事和碎片
2. 按时间线整理关键事件
3. 生成"恋爱回忆录"草稿
4. 统计关系数据（总时长、互动次数、情感曲线）

**输出示例：**

```markdown
## 你们的故事

### 相识
[第一次注意到 TA 的叙事...]

### 相知
[第一次对话的叙事...]

### 相恋
[暧昧期的关键事件...]

### 表白
[表白场景的叙事...]

---

📊 关系数据
- 认识时长：45 天
- 总叙事：23 篇
- 总字数：12,450
- 关键时刻：8 个
```

## 6. 技术实现要点

### 6.1 进度检测算法

以下为当前 TypeScript 模块的职责示意：

```text
def detect_phase_signals(narrative_text, current_phase):
    """
    分析叙事文本，检测阶段推进信号
    返回：(signals: list, score: int)
    """
    signals = []
    score = 0

    # Phase 0 -> 1 检测
    if current_phase == 0:
        if has_dialogue(narrative_text):
            signals.append("有对话")
            score += 20
        if has_name_exchange(narrative_text):
            signals.append("知道名字")
            score += 20
        if has_contact_exchange(narrative_text):
            signals.append("有联系方式")
            score += 20

    # Phase 1 -> 2 检测
    elif current_phase == 1:
        if has_physical_contact(narrative_text):
            signals.append("身体接触")
            score += 25
        if has_late_night_chat(narrative_text):
            signals.append("深夜聊天")
            score += 25
        if has_alone_time(narrative_text):
            signals.append("单独相处")
            score += 25
        if has_gift_exchange(narrative_text):
            signals.append("送礼物")
            score += 25

    return signals, score
```

### 6.2 阶段推进阈值

| 当前阶段 | 目标阶段 | 阈值 | 检测方式 |
|---------|---------|------|---------|
| 0 | 1 | 60分 | 自动检测 + 用户确认 |
| 1 | 2 | 70分 | 自动检测 + 用户确认 |
| 2 | 3 | - | 用户手动触发 |
| 3 | 4 | - | 用户手动触发 |

## 10. 术语

- **关系阶段（Phase）：** 当前实现为五个阶段，本文原始方案曾定义四个阶段
- **阶段信号（Signal）：** 叙事中暗示关系推进的关键词或情节
- **阶段阈值（Threshold）：** 进入下一阶段所需的最低信号分数
- **表白叙事（Confession Narrative）：** 专门描写表白场景的叙事类型
- **关系回顾（Relationship Review）：** 汇总所有叙事生成的完整关系时间线
