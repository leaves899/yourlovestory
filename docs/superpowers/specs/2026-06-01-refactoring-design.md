# 重构设计文档

> 重新设计 yourcrush 项目的架构，保持现有功能，改善可维护性、可测试性、可扩展性、前端适配性

**状态**：已批准
**作者**：AI Assistant

## 1. 目标

重新设计 yourcrush 项目的架构，保持现有功能，但改善：

- **可维护性**：代码清晰，易于理解和修改
- **可测试性**：易于编写和运行测试
- **可扩展性**：易于添加新功能和模块
- **前端适配性**：易于连接到前端 UI

**优先级**：可维护性 > 可测试性 > 可扩展性 > 前端适配性

---

## 2. 架构方案

### 2.1 采用方案：混合架构

```
scripts/
├── day/                    # day 模块（按职责拆分）
│   ├── __init__.py
│   ├── pipeline.py          # 主入口，协调各模块
│   ├── service.py           # 服务层，封装 API
│   ├── validators/          # 验证器
│   │   ├── __init__.py
│   │   ├── timeline.py      # 时间线检查
│   │   ├── keywords.py      # 关键词矛盾检查
│   │   └── count.py         # 次数一致性检查
│   ├── extractors/          # 提取器
│   │   ├── __init__.py
│   │   ├── intimate.py      # 亲密数据提取
│   │   └── cycle.py         # 周期数据提取
│   ├── updaters/            # 更新器
│   │   ├── __init__.py
│   │   ├── meta.py          # meta.json 更新
│   │   ├── memory.py        # memory.md 更新
│   │   └── prompt.py        # PROMPT.md 更新
│   ├── generators/          # 生成器
│   │   ├── __init__.py
│   │   ├── intimate.py      # 亲密档案生成
│   │   └── context.py       # CONTEXT.md 生成
│   └── sync/                # 同步器
│       ├── __init__.py
│       ├── persona.py       # persona_core.md 同步
│       └── weekday.py       # WEEKDAY.md 同步
├── fragment/               # 碎片日记模块
│   ├── __init__.py
│   ├── models.py
│   ├── state_machine.py
│   ├── manager.py
│   ├── prompt_generator.py
│   ├── tag_recommender.py
│   ├── blind_matcher.py
│   └── utils.py
├── parsers/                # 解析器模块
│   ├── __init__.py
│   ├── wechat_parser.py
│   ├── qq_parser.py
│   └── social_parser.py
├── service/                # 服务层（新增）
│   ├── __init__.py
│   ├── day_service.py
│   └── fragment_service.py
└── utils/                  # 工具函数（新增）
    ├── __init__.py
    ├── file_utils.py
    └── date_utils.py
```

### 2.2 设计理由

1. **符合当前项目状态**：项目已经有清晰的模块划分（day、fragment、parsers），只需要添加服务层和工具函数层
2. **符合优先级**：可维护性、可测试性、可扩展性、前端适配性
3. **符合重构策略**：只重构 day 模块，其他模块只移动位置
4. **符合测试策略**：先写集成测试，再补充单元测试

## 4. 测试策略

### 4.1 测试类型

- **集成测试**：测试整个 pipeline 的输入输出
- **单元测试**：为每个函数写测试

### 4.2 测试覆盖

测试覆盖所有功能和所有边界情况。

### 4.3 测试顺序

1. 先写集成测试 — 测试 day_pipeline.py 的输入输出
2. 重构 day 模块 — 按职责拆分，添加服务层
3. 补充单元测试 — 为每个模块写测试

## 14. 风险和应对

### 14.1 导入路径变更

**风险**：移动文件后，所有导入路径都需要更新

**应对**：批量移动文件，然后统一修复导入

### 14.2 测试覆盖不足

**风险**：可能遗漏某些边界情况

**应对**：测试覆盖所有功能和所有边界情况

### 14.3 依赖关系复杂

**风险**：模块之间的依赖可能比预期复杂

**应对**：仔细分析依赖关系，确保模块之间低耦合

### 14.4 时间不足

**风险**：可能无法在 3-5 天内完成

**应对**：优先重构核心模块，其他模块可以延后
